# media/

Marca de KITE Local: el icono y las imágenes derivadas de él.

| Archivo | Para qué |
|---|---|
| `kite-icon.svg` | El icono original, 24×24, tal cual. Es la fuente de todo lo demás. |
| `favicon.svg` | El mismo dibujo escalado ×1,2 sobre su centro para llenar la casilla; a 16 px el original se queda pequeño dentro de su cuadrado. |
| `favicon.ico` | 16, 32 y 48 px en un solo `.ico` (con PNG dentro), para servirlo como `/favicon.ico` desde la raíz de un sitio. |
| `favicon-16.png`, `favicon-32.png` | Los mismos tamaños sueltos. |
| `apple-touch-icon.png` | 180×180 con fondo `#f7f7f5`: iOS no respeta la transparencia y pondría negro detrás. |
| `kite-icon-512.png` | El icono grande, por si hace falta un PWA o una tienda. |
| `kite-demo.gif` | El GIF de la portada del README: arrastrar un KMZ a la aplicación y verlo abierto (1100×700, unos 13 s, menos de 1 MB). Lo genera `tools/demo-gif.mjs`, no se toca a mano (ver abajo). |
| `kite-fresnel.gif`, `kite-geotiff.gif`, `kite-wikipedia.gif` | The three clips of «See it in action» in the README (about 0.8, 0.8 and 1.1 MB): a route profile with line of sight and Fresnel zone, a GeoTIFF elevation model dropped onto the panel, and Wikipedia articles plus an itinerary. Made with REAL data (live IGN and Wikipedia, see below); generated by `tools/demo-scenes.mjs`, never by hand. |
| `kite-social.png` | 1200×630 (unos 400 KB), la imagen de vista previa al compartir el enlace (`og:image` / `twitter:image`) y, subida a mano, la del repositorio en GitHub (ver abajo). Una tarjeta en inglés con una fotografía de la aplicación de verdad; la genera `tools/social-image.mjs`. |

## Cómo se enlazan

- **El favicon NO se enlaza desde aquí**: va incrustado como `data:` URI en
  `src/index.html`, porque el producto es un único archivo que se abre con
  doble clic y una ruta a `media/` no existiría junto a él. Si se cambia el
  icono hay que regenerar también esa URI.
- **La imagen social sí se enlaza por URL absoluta**, a `raw.githubusercontent.com`:
  ningún rastreador de redes sociales resuelve rutas relativas (la descargan
  desde sus propios servidores) ni dibuja SVG, así que tiene que ser un PNG
  con URL completa.

## Cómo se regeneran

**`kite-demo.gif`**: `npm run demo-gif` (hace falta red, por las teselas de OpenStreetMap; `-- --sin-fondo` para iterar el guion sin ella y `-- --fotogramas carpeta` para volcar cada fotograma como PNG y revisarlo). Arranca la aplicación limpia en inglés, «arrastra» `docs/ejemplos/operacion-sierra.kmz` con los mismos eventos `dragover` y `drop` que un archivo del escritorio (el cursor y el archivo que se ve moverse son dos elementos dibujados encima de la página: el navegador no deja a un script abrir una sesión de arrastre del sistema), y recorre lo que sale. Los fotogramas son capturas de la página, codificadas con una sola paleta de 255 colores y escribiendo solo los píxeles que cambian de un fotograma al siguiente. **Se regenera cuando cambia la interfaz que enseña** (caja de búsqueda, árbol, zona de soltar) y en cada release, junto con las capturas del manual.

**The three showcase clips**: `npm run demo-scenes` (all three, about 2.5 minutes), `-- fresnel geotiff` for some, `-- --sin-fondo` to iterate without OpenStreetMap tiles and `-- --fotogramas carpeta` to dump every frame as a PNG (it also lists the long pauses, the moments the clip is about, and, if a step fails, saves a screenshot and lists the context menus that were open). They need a network: the OpenStreetMap tiles AND the services whose answers are shown. **What is real, on purpose** (a demo with invented terrain would be a lie about what the tool does): the route profile is downloaded LIVE from the IGN's WCS services; the GeoTIFF is the IGN's MDT25 of the Sierra de Guadarrama, downloaded when the script runs and rebuilt as a proper tiled COG with overviews (`tests/browser/_tiff.mjs`) so that the application's own warning about non-COG files does not show; the Wikipedia articles are asked live from en.wikipedia.org. **The one stand-in is the itinerary**: with no key the script answers the openrouteservice request with a stand-in in the documented format (the same one the tests use, which is synthetic: `.claude/rules/routing.md`), and the README caption says so; with `ORS_API_KEY=… npm run demo-scenes -- wikipedia` it asks the real service (the key goes to that server only and is never printed or written). The result changes a little with each run because the services are live, so each script looks for the moment it shows by what the page says, not by a fixed number. Like the cover GIF, they share the cursor, the recorder and the encoder in `tools/_gif.mjs`. **Regenerate them when the interface they show changes and at each release**, and look at the frames before accepting them.

**`kite-social.png`**: `npm run social-image` (hace falta red; `-- --sin-fondo` para iterar el diseño). Abre la aplicación en inglés con el KMZ de ejemplo, la fotografía y la coloca en una tarjeta de 1200×630 (el tamaño que declara `og:image:width/height` en `src/index.html`: cambiarlo exige cambiar también esas dos líneas). Se regenera cuando cambia la interfaz que enseña. **GitHub no tiene API para su «Social preview»**: tras regenerarla, se sube a mano en Settings › General › Social preview (pide menos de 1 MB; el script avisa si se pasa).

**Los demás PNG** salen de rasterizar el SVG con Chromium (`--headless`), dibujándolo
sobre un `<canvas>` al tamaño exacto y leyendo `toDataURL`. Ojo: capturar con
`--screenshot` a ventanas pequeñas en esta VM sin GPU deja la imagen a medio
pintar; el camino del `<canvas>` sí es fiable.
